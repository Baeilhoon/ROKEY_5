```
┌─────────────────────────────────────────────────────────┐
│                 PC (Ubuntu 22.04)                      │
│  ┌─────────────────────────────────────────────────┐   │
│  │        ROS2 Master (Humble)                    │   │
│  │                                                 │   │
│  │  ┌──────────────────────────────────────────┐  │   │
│  │  │  Conveyor State Machine Node (C++)      │  │   │
│  │  │                                          │  │   │
│  │  │  ├─ /conveyor/state (topic)             │  │   │
│  │  │  ├─ /conveyor/command (service)        │  │   │
│  │  │  └─ State: IDLE/MOVING/WAITING/ERR    │  │   │
│  │  └──────────────────────────────────────────┘  │   │
│  │         │                   ▲                 │   │
│  │  ┌──────▼───────────────────│──────────────┐  │   │
│  │  │  Robot Arm Coordinator   │   (C++)      │  │   │
│  │  │  (Receives conveyor state)             │  │   │
│  │  └────────────────────────────────────────┘  │   │
│  │                                                │   │
│  │  ┌──────────────────────────────────────────┐  │   │
│  │  │  Firebase Logger (Python)                │  │   │
│  │  │  (All events to cloud)                   │  │   │
│  │  └────────────────────────┬─────────────────┘  │   │
│  └─────────────────────────────────────────────────┘   │
│                    │                                    │
│         [USB-Serial Bridge]                             │
│                    │                                    │
└────────────────────┼────────────────────────────────────┘
                     │
        ┌────────────▼──────────────┐
        │   Arduino UNO/MEGA        │
        │   (Firmware)              │
        │                           │
        │  ├─ IR Sensor Input       │
        │  ├─ Step Motor Control    │
        │  ├─ Debouncing Logic      │
        │  ├─ State Flags           │
        │  └─ ACK Signaling         │
        └────────────┬──────────────┘
                     │
        ┌────────────┴──────────────┐
        │                           │

        │                           │

        ├── Step Motor             │

```

### 메시지 흐름

```
1. IR Sensor 감지
   IR → 디바운싱 → 이벤트 생성
   
2. Arduino 처리
   이벤트 → 상태 전환 → 모터 제어
   
3. ROS2 발행
   상태 → /conveyor/state 토픽
   
4. 로봇팔 구독
   /conveyor/state 수신 → 의사 결정
```

### CPU 관리 전략

```
정상 상황 (CPU < 75%)
  └─ Nav2 + Vision + LLM 모두 활성

로드 증가 (75% < CPU < 85%)
  └─ LLM 비활성화 (자율주행 + 감지만)

높은 로드 (85% < CPU < 95%)
  └─ Vision 일부 비활성 (자율주행만 유지)

긴급 (CPU > 95%)
  └─ Nav2만 활성화 (안전 주행 모드)
```

## 📚 아키텍처 설계 원칙

### 1. 계층화 (Layering)
```
Application Layer (의사결정)
    ↓
Middleware (조율)
    ↓
Hardware Layer (제어)
```

### 2. 분리 우려사항 (Separation of Concerns)
```
각 모듈은 명확한 책임 하나만 가짐
- Vision: 객체 감지만
- Navigator: 경로 계획만
- State Machine: 상태 전환만
```

### 3. 인터페이스 명확성
```
모듈 간 통신은 명확한 인터페이스를 통해서만
- ROS2 Topic (메시징)
- ROS2 Service (요청-응답)
- 구조화된 메시지 형식
```

### 4. 확장성
```
새로운 기능 추가 시 기존 코드 수정 최소화
- 플러그인 아키텍처
- 상태 머신 확장 가능
- 우선순위 기반 처리
```
